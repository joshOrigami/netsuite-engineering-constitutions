# Code of Conduct

This project exists to share ideas, specifications, and constraints that help
teams build safer and more understandable NetSuite systems.

To support that goal, all participants are expected to follow these guidelines.

---

## Our commitment

We are committed to maintaining a respectful, professional, and welcoming
environment for everyone who participates in this project.

This includes contributors, reviewers, maintainers, and anyone engaging through
issues, pull requests, or discussions.

---

## Expected behavior

We expect all participants to:

- communicate with respect and professionalism
- focus on ideas and arguments, not individuals
- assume good intent unless proven otherwise
- be open to constructive feedback
- disagree thoughtfully and explain reasoning
- respect different levels of experience and perspective

Strong opinions are welcome. Personal attacks are not.

---

## Unacceptable behavior

Unacceptable behavior includes, but is not limited to:

- harassment or discrimination of any kind
- personal insults or derogatory comments
- dismissive or hostile communication
- intimidation or threats
- repeated disruption of discussion
- inappropriate or unprofessional conduct

This applies to all project spaces.

---

## Scope

This Code of Conduct applies to:
- GitHub issues
- pull requests
- comments and discussions
- any other project-related communication

---

## Enforcement

Maintainers are responsible for enforcing this Code of Conduct.

If unacceptable behavior occurs, maintainers may:
- request changes to behavior
- remove comments or contributions
- temporarily or permanently restrict participation

Enforcement actions are taken to protect the community and the project.

---

## Reporting concerns

If you experience or witness behavior that violates this Code of Conduct,
please contact the maintainers privately via GitHub.

All reports will be handled discreetly and respectfully.

---

## Closing note

This project values thoughtful disagreement, clarity of thought, and professional
collaboration.

We’re here to make assumptions explicit — not to create friction.
